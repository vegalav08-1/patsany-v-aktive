# Пацаны в активе

Мобильная аркада на 90 секунд: четыре друга с настоящими фотографическими головами собирают выручку, покупают пять бизнесов и проходят пять визуальных этапов. Один палец, три дорожки, каждый забег с нуля. TypeScript + Vite + Canvas 2D, без серверной части и runtime-зависимостей.

**[Играть — Пацаны в активе](https://vegalav08-1.github.io/patsany-v-aktive/)**. Эту ссылку можно отправлять друзьям: игра открывается в браузере без регистрации и установки. После забега «Поделиться» создаёт PNG результата и ссылку на ту же трассу.

Выполненные проверки и ограничения среды: [итоговый отчёт](reports/QA.md).

## Запуск

Нужен Node.js 22.12+ (рекомендуется 24). Все игровые изображения уже подготовлены и лежат в `public/assets`. Исходная фотография, Python и сервис обработки изображений для установки, CI и сборки не нужны.

```sh
npm install
npm run dev
```

Для точного повторения установки используйте `npm ci`: версии зафиксированы в `package-lock.json`.

## Команды

| Команда | Назначение |
| --- | --- |
| `npm run dev` | Локальная игра, адрес печатает Vite |
| `npm run typecheck` | Строгая проверка TypeScript |
| `npm test` | Тесты чистой игровой модели |
| `npm run balance` | 160 полных модельных забегов, результаты в `reports/balance.*` |
| `npx playwright install chromium webkit` | Однократная установка тестовых браузеров |
| `npm run test:e2e` | Браузерные smoke-тесты в Chromium и WebKit |
| `npm run build` | Проверка типов и production-сборка в `dist` |
| `npm run preview` | Локальный просмотр `dist` |
| `npm run test:production` | Полные production-забеги на `/` и `/business-game/`, оба браузера |
| `npm run package` | Проверка состава/размера `dist` и архив `business-game-dist.zip` (macOS/Linux, утилита zip) |

`test:production` ожидает готовый `dist`, дополнительно собирает `dist-prefixed`. Он выполняет реальные production-обработчики и RAF через виртуальное время Playwright. Это браузерная автоматизация, не проверка на физическом телефоне. Тестовые методы `window.__game` доступны только в dev или явной сборке `--mode test`; обычный `npm run build` удаляет их.

## Управление и правила

Тап переводит на выбранную дорожку. Горизонтальный свайп — на соседнюю. На компьютере работают стрелки и A/D, мышь; Escape/P ставит на паузу. Кнопки интерфейса не меняют дорожку. Скрытие вкладки и потеря фокуса останавливают игру; продолжение — по кнопке.

Зелёная выручка добавляет наличные. Золотой бизнес покупается при касании, если денег достаточно. Красный убыток списывает долю наличных, сохраняя активы; повторное списание защищено интервалом 0,8 секунды. Портфель не сбрасывается от столкновений, забег не прерывается.

Капитал = наличные + цены купленных активов. Покупка переводит деньги в актив без создания капитала. Доход учитывается только за активное игровое время, дробные рубли сохраняются между кадрами; интерфейс округляет вниз до целого рубля. Образ открывается по максимальному капиталу за забег и не откатывается после убытка. На финише показаны фактический капитал и максимальный открытый статус.

Экономика условная, аркадная. Подробности модельных прогонов — в `reports/balance.md`. Это тестовые политики с заданными ошибками, не исследование поведения людей.

## Настройка

- `src/config/game.ts`: цены, доход, номиналы, штрафы, время, пороги, скорость, частота предложений и препятствий.
- `src/config/heroes.ts`: стартовые имена, цвета, проверенные координаты голов и параметры их посадки на тело. Имя также можно изменить в меню; оно ограничено 20 символами и выводится безопасно как текст.
- `public/assets/head-*.webp`: готовые головы с прозрачностью. `friends.webp` — оптимизированная заставка. У производных файлов удалены EXIF/ICC/XMP; исходник исключён из Git и сайта.
- `scripts/prepare-assets.py`: необязательная локальная обработка исходника Pillow, ручные сглаженные контуры. Путь к исходному фото задаётся в скрипте. Не запускается при `build` или в CI.
- `src/game/model.ts`: независимая от Canvas модель. `renderer.ts`: локальная графика, анимации и декорации. `input.ts`: жесты и клавиатура. `src/ui`: сохранения, форматирование, PNG-карточка.

## Челлендж и данные

Ссылка `?seed=любая-строка&v=1` воспроизводит базовые дорожки и препятствия той же версии игры. Номиналы и предложения зависят от прогресса. Частицы используют отдельную случайность. «Повторить трассу» сохраняет seed, «Новая трасса» создаёт новый. Изменение логики маршрута требует обновить `GAME.version`; ссылки и подписи используют эту константу.

Выбор героя, имена, звук и 10 лучших результатов хранятся только в localStorage этого браузера. «Рекорды на этом устройстве» не является общей таблицей друзей. При недоступности хранения игра работает в памяти вкладки. Нет аналитики, CDN, аккаунтов, сервис-воркера и офлайн-дохода. Результаты и seed не защищены от модификации пользователем: это допустимо для дружеского челленджа, серверной защиты нет.

Результат можно отправить через системный share API с PNG, если браузер поддерживает файлы. Запасной путь всегда показывает PNG, сохранение, текст и ссылку. При запрете clipboard текст выделяется для ручного копирования. На localhost показано предупреждение, что ссылка не доступна друзьям; публичный домен не подставляется.

## GitHub Pages

Репозиторий игры: [vegalav08-1/patsany-v-aktive](https://github.com/vegalav08-1/patsany-v-aktive), default branch — `main`. Репозиторий открыт, игра опубликована с разрешения владельца: **https://vegalav08-1.github.io/patsany-v-aktive/**. [Успешный запуск публикации](https://github.com/vegalav08-1/patsany-v-aktive/actions/runs/33937101500).

Для обновления опубликованной игры:

1. Используйте проверенный код ветки `main`, включая `public/assets` и lockfile. Не включайте `assets/source/friends.jpg`, `node_modules`, тестовые скриншоты и секреты. Папка `dist` собирается в CI.
2. В **Settings → Pages** уже настроен источник **GitHub Actions**. При необходимости задайте approval для окружения `github-pages`.
3. Запустите **Actions → Publish GitHub Pages → Run workflow** на default branch. Сначала пройдут typecheck, модельные, браузерные и production-проверки на корне и в подкаталоге, затем сборка с реальным путём Pages и публикация. Фактический адрес появится в выполненном deploy job и в Settings → Pages.

Workflow `.github/workflows/pages.yml` запускается только вручную и только с default branch; push и pull request выполняют только проверки из `checks.yml`. Build job получает `contents: read` и `pages: read` для чтения настроек сайта. Права записи Pages и OIDC есть только у deploy job. Личные токены не используются. Официальный процесс: [GitHub Pages с собственным workflow](https://docs.github.com/en/pages/getting-started-with-github-pages/using-custom-workflows-with-github-pages); [права чтения настроек Pages](https://docs.github.com/en/rest/pages/pages#get-a-github-pages-site).

Версии официальных Actions сверены с опубликованными релизами: [checkout v7](https://github.com/actions/checkout/releases/tag/v7.0.1), [setup-node v7](https://github.com/actions/setup-node/releases/tag/v7.0.0), [configure-pages v6](https://github.com/actions/configure-pages/releases/tag/v6.0.0), [upload-pages-artifact v5](https://github.com/actions/upload-pages-artifact/releases/tag/v5.0.0), [deploy-pages v5](https://github.com/actions/deploy-pages/releases/tag/v5.0.1). Workflow использует `ubuntu-latest` и Node.js 24.

`actions/configure-pages` передаёт реальный `base_path` в Vite. Это поддерживает корневой сайт `owner.github.io` и проект `owner.github.io/repository/`. Все картинки используют Vite base, а ссылка челленджа строится из фактического адреса открытой страницы. Серверные rewrite не нужны.

По умолчанию `base: './'`: готовый архив переносим и на корень, и в подкаталог. Явная сборка под путь:

```sh
VITE_BASE_PATH=/repository/ npm run build
# Для корневого сайта:
VITE_BASE_PATH=/ npm run build
```

`business-game-dist.zip` содержит только браузерные файлы и `.nojekyll`. Он пригоден для любого статического хостинга. Фото друзей входит в игру только в оптимизированном виде; публикация делает эти изображения доступными посетителям сайта.
